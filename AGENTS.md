# Poker Odds Lab DOX

## Purpose
- Poker Odds Lab is a Rust-native poker equity calculator with a static browser UI and an iOS wrapper.
- The root owns workspace-level Rust configuration, top-level docs, `index.html`, static asset wiring, generated benchmark output policy, and cross-cutting DOX rules.
- The app supports Hold'em, PLO4, PLO5, and PLO6 through the `native-sim` engine.

## Ownership
- `Cargo.toml` and `Cargo.lock` define the Rust workspace for `backend-rs-native`, `native-sim`, and `ios/native-sim-ffi`.
- `index.html` is the primary web shell served by the backend and copied into the iOS bundle.
- `.bench/` contains benchmark outputs generated by `scripts/bench.sh`; do not treat it as source.
- `target/` contains Rust build artifacts; do not edit or document generated contents there.
- `.codex/`, `.git/`, and local OS metadata are outside project behavior contracts.

## Local Contracts
- AGENTS.md files are binding work contracts for their subtrees.
- Work products, source materials, instructions, records, assets, and durable docs must stay understandable from the nearest applicable AGENTS.md plus every parent AGENTS.md above it.
- Before editing, read this file, identify every target path, walk from the repository root to each target path, and read every AGENTS.md found along the route.
- If a parent AGENTS.md lists a child AGENTS.md whose scope contains the path, read that child and continue from there.
- The nearest AGENTS.md controls local details; no child AGENTS.md may weaken these root DOX rules.
- Every meaningful change requires a DOX pass before closeout: re-check changed paths against the DOX chain, update nearest owning docs and affected indexes, remove stale or contradictory text, and report docs intentionally left unchanged.
- Create a child AGENTS.md when a folder becomes a durable boundary with its own purpose, rules, responsibilities, workflow, materials, or quality standards.
- Keep docs concise and operational. Document stable contracts, not diary entries.

## Work Guidance
- Use the latest stable versions of dependencies, libraries, frameworks, and tools when changing dependency policy or adding new tooling.
- Prefer maintained APIs, current architecture patterns, and long-term maintainability over deprecated or legacy approaches.
- Keep source-of-truth changes in primary source folders; update copied or bundled artifacts through existing sync scripts.
- Keep broad rules in parent docs and concrete implementation details in child docs.
- Do not duplicate rules across many files unless each scope needs a local version.
- Delete stale notes instead of explaining history.

## User Preferences
- Prefer latest stable dependencies, actively maintained technologies, modern best practices, compatibility, security, performance, and long-term maintainability across the stack.

## Verification
- For Rust workspace changes, run `cargo check --workspace` at minimum.
- For backend behavior changes, prefer `cargo test --workspace` when runtime allows.
- For frontend changes, run the Rust backend with `cargo run -p odds --release` and verify the served app at `http://localhost:8789/index.html` when behavior or UI is affected.
- For deployment script changes, run shell syntax checks with `bash -n` on changed scripts.
- For iOS bridge or bundle changes, run the relevant sync/build scripts when the local platform supports them, then verify in Xcode or document why that was not possible.

## Child DOX Index
- `src/AGENTS.md`: Browser frontend modules, styles, live worker, range parsing helpers, and percentile table modules.
- `backend-rs-native/AGENTS.md`: Axum HTTP server, API handlers, static serving, request validation, runtime limits, and backend integration with `native-sim`.
- `native-sim/AGENTS.md`: Core Rust simulation engine, CLI JSON runner, exact percentile tables, range plans, and evaluator logic.
- `ios/AGENTS.md`: iOS packaging boundary, Swift app wrapper, Rust FFI crate, bundled web asset policy, and Xcode integration.
- `deploy/AGENTS.md`: LXC deployment scripts, systemd unit, nginx config, install/update workflow, and production runtime assumptions.
- `scripts/AGENTS.md`: Root utility scripts for benchmarking and static precompression.
